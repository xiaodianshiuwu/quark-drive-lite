## 主要缺陷与修复

| 优先级 | 原问题及影响 | 已实施修复 |
|---|---|---|
| P1 | 上传分片签名含 partNumber/uploadId，实际 PUT URL 没有，正常分片链路无法可靠工作 | 实际 URL 带齐参数，并验证与签名一致 |
| P1 | 实际 pds 存储端拒绝并发 PUT，返回 HTTP 400 / PartNotSequential | 并发预读；签名与 PUT 按连续编号执行。随机多分片上传已真实通过 |
| P1 | 请求收到响应头后解除中止监听，正在读取的下载无法及时停止 | 中止和超时生命周期覆盖整个响应体 |
| P1 | 暂停后立即继续、重试运行中任务、取消时先清文件，可能产生多个执行器和文件竞态 | 按真实执行器占用并发；等待退出后调度及清理；限制重试状态 |
| P1 | 同名并发下载共享临时路径，别的 fid 可被续写；收尾可能覆盖后来创建的文件 | 路径占用、临时文件归属校验、独占创建目标；不覆盖原有文件 |
| P1 | 分片失败后其他 worker 继续写已关闭句柄；仅按长度校验 Range；分片 200 未真正降级 | 中止并等待所有 worker；校验 Content-Range；安全降级单流 |

## 仍然存在的限制

1. 文件列表最多显示 **4000 项**，没有真正的虚拟滚动。
2. 传输队列只在内存保存，不能在应用重启后自动恢复队列。下载临时数据可复用；上传检查点只在当前进程保留。
3. 当前上传目标要求顺序 PUT。界面的上传分片预读并发不能理解成同时上传多个分片。
4. 本次实测文件为 8.01 MB 随机上传文件及约 30.07 MB 已有下载文件。**多 GB 文件、长时间弱网与官方完整性能对比尚未实测**。
5. 尚未确认的异步任务状态数值、登录资料字段仍保持明确降级，不猜测语义。
6. 扫码登录与操作系统原生文件拖拽属于用户交互，本地 File 路径提取已在源码版和便携版分别实测；本次没有代替用户重新扫码。
7. 官方方案 B 隐藏三项导航并减负，**并未彻底删除官方附加能力，也不能保证风控结果**。
8. 历史逆向、Cookie 解密和第三方协议原型没有逐个对真实数据执行。它们不是便携版生产入口，不能以语法通过认定全部工具均可安全直接运行。
