## 已修复问题

- macOS 系统钥匙串授权会阻塞启动，打包应用反复要求密码。正式存储改为 QCK2 / AES-256-GCM，本机随机密钥与密文共同保存；Windows、Linux 同样免系统密码。Chromium 登录分区仅驻内存，macOS/Linux 使用本应用范围的浏览器存储开关。
- 旧 QCK1 在 macOS 通过已准备的独立旧运行时读取，再写入 QCK2，由当前源码/打包运行时回读；现代系统后端保留异步处理。这样覆盖真实旧密文迁移，同时避免 CI 中新 KeychainV2 初始化许可的差异。
- 旧 QCK1 密文保留备份，显式迁移仍可读；普通 GUI 不触发旧钥匙串授权，可重新扫码保存新格式。损坏/错密钥/认证失败不覆盖原密文。
- 设置落盘失败后主进程和界面仍可能展示未保存的新设置。改为写入成功后更新，失败恢复已保存值。
- Cookie 已全部过期仍可能判为已登录。登录状态改用当前可用 Cookie。
- HTTP UA 固定 Chromium 版本与运行时不一致。Electron 使用真实 Chromium 版本，Node 工具保留已取证兼容版本；夸克协议标识保持不变。
- 主窗口导航与弹窗拦截安装过晚。窗口创建时立即拦截，覆盖登录资料读取阶段。
- Mac 在受文件提供者影响的 Documents 内签名会受 FinderInfo 竞态干扰。应用构建与签名改在本机缓存目录完成，验收按清单定位。
- Windows 便携工具二次重写 app.asar 会影响构建完整性。改为检查版本/源码字节与 fuses 后完整复制已构建目录；CI 分别启动目录版和便携版，ASAR 读取使用当前系统原生路径分隔符。
- 旧下载开发工具只复制密文、未复制 QCK2 密钥。补全平台用户目录与测试密钥复制，禁止测试覆盖真实用户目录。

## 明确保留的验收边界

- 按本次约定，多 GB 真正完整上传下载回读待后续验收；当前完成规模为 32 MiB。
- QCK2 的密钥与密文同目录，能避免明文保存与检测篡改，但不具备系统钥匙串的应用隔离；备份/迁移必须同时保存 session.bin 和 session.key。
- 旧格式显式迁移可能需要一次系统授权；日常应用启动不调用该接口。
- macOS 使用 ad-hoc 签名，未做 Developer ID 公证；Windows 未做发行者签名。此版本作为预发布提供。
