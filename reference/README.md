## 证据优先级

判断一个端点或参数是否可以采用时，按以下顺序取证：

```
① 官方 PC 客户端应用包的反编译产物（能拿到真实参数名与调用方式）
        ↓
② 真实账号实测（观察结果集是否真的随参数变化）
        ↓
③ 开源驱动源码（交叉印证，可能存在版本滞后）
```

**任何端点或参数，若未在上述来源中出现过，不得写进实现代码。** 新发现必须补录到 [`docs/API_NOTES.md`](../docs/API_NOTES.md) 并标注证据来源。

## 可复用的验证方法

### 路由存在性探测（无需登录）

服务端为 Spring Boot 应用：

- 用**错误的方法**请求**存在**的路由 → `405` + `HttpRequestMethodNotSupportedException`，说明路径存在
- 请求**不存在**的路由 → `404` + `No message available`，说明路径不存在

据此可以在未登录状态下证伪流传的错误端点。

### 判断参数是否真的生效

**不能只看「有没有报错」或「有没有返回结果」**，必须验证**结果集随参数变化**。

以搜索参数为例（真实账号实测）：

| 参数 | 结果 | 判定 |
|---|---|---|
| `q` | 完整文件名 → 1 项；前缀 → 5 项；单字符 → 14 项 | ✅ 有效 |
| `keyword` / `_key` / `key` / `file_name` / `query` | 一律返回根目录默认 20 项 | ❌ 被服务端静默忽略 |

后一组参数看起来「也成功了」（HTTP 200、`code` 为 0、有结果），但实际是服务端忽略了参数并返回默认列表。只检查是否报错会得出完全错误的结论。
